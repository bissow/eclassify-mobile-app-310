# Test / Default OTP Provider (123456)

**Date:** 24.09.2026  
**Module / Area:** Authentication & OTP Service Provider (`lib/core/enums/otp_provider_type.dart`, `lib/core/models/system_settings.dart`)  
**Status:** Implemented & Verified  

---

## 1. Overview

Added support for the **Test / Default OTP** service provider (`test`) configured via the backend admin panel (`Settings > OTP Provider Settings`). When active, mobile registration and phone login flows route verification through the backend test provider using `123456` without relying on SMS gateways.

---

## 2. Key Changes

1. **`lib/core/enums/otp_provider_type.dart`**:
   - Added `test` enum value to `OtpProviderType`.
   - Updated `OtpProviderType.fromRaw()` to case-insensitively parse `'test'`, `'test_otp'`, and `'default'`.
   - Added `bool get isFirebase => this == OtpProviderType.firebase;` helper property.

2. **`lib/core/models/system_settings.dart`**:
   - Hardened `otp_service_provider` parsing in `SystemSettings.fromJson()` with null-safety fallback to ensure seamless deserialization.

3. **Routing (`lib/features/auth/cubits/base_otp_cubit.dart`)**:
   - Non-Firebase providers (`test`, `twilio`, `twoFactor`) automatically route through `ThirdPartyOtpService` to `/api/get-otp` and `/api/verify-otp`.
