## 1. Issues Addressed

### Issue 1: Awesome Notifications Background Action Handler
**Log:**
```text
W/Android: [Awesome Notifications](10512): Attention: there is no valid static method to receive notification actions in background (AwesomeNotificationsPlugin:1416)
I/flutter (10512): [Awesome Notifications - ERROR]: onActionNotificationMethod is not a valid global or static method. (MethodChannelAwesomeNotifications:441)
```

**Root Cause:**  
`AwesomeNotifications.setListeners` requires `onActionReceivedMethod` to be a top-level function or a `static` method annotated with `@pragma('vm:entry-point')`. The previous implementation passed an anonymous inline closure `(receivedAction) async { ... }`. Because anonymous closures cannot produce a native callback handle via `PluginUtilities.getCallbackHandle`, the plugin logged an error and could not dispatch notification clicks when the app was in the background or killed.

**Fix:**  
In `lib/features/notification/helpers/notification_utility.dart`:
- Defined a static callback `_onForegroundNotificationTap`.
- Created an explicit static method annotated with `@pragma('vm:entry-point')`:
  ```dart
  @pragma('vm:entry-point')
  static Future<void> onActionReceivedMethod(
    ReceivedAction receivedAction,
  ) async {
    if (receivedAction.payload != null) {
      _onForegroundNotificationTap?.call(receivedAction.payload!);
    }
  }
  ```
- Passed `NotificationUtility.onActionReceivedMethod` into `_awesomeInstance.setListeners(...)`.

### Issue 2: Location "No nearby city found" Unhandled Crash
**Log:**
```text
I/flutter (10512): 💡 GET /api/get-location {lat: 22.5814274, lng: 88.4098771, lang: en}
I/flutter (10512): │ No nearby city found
E/flutter (10512): [ERROR:flutter/runtime/dart_vm_initializer.cc(40)] Unhandled Exception: No nearby city found
E/flutter (10512): #0      Api.get.<anonymous closure> (package:eClassify/core/network/api.dart:168:9)
...
E/flutter (10512): #6      RootLocationResolverMixin._getLocation (package:eClassify/features/home/screens/mixins/root_location_resolver_mixin.dart:146:24)
```

**Root Cause:**
1. **Backend side:** The backend endpoint `/api/get-location` checks whether the coordinates (`lat: 22.5814274, lng: 88.4098771` - Kolkata, India) exist within a configured city radius in the database (or via Google Maps API). When the coordinates are not covered by any city currently listed in the Admin Panel (`Admin Panel -> Locations -> Cities`), the backend responds with `{"error": true, "message": "No nearby city found"}`.
2. **App side:** `LocationUtility._getLiveLocation()` and `RootLocationResolverMixin._getLocation()` did not wrap `getLeafLocationFromLatLng` in a `try/catch`. When `Api.get` threw `ApiException("No nearby city found")`, the unhandled exception crashed location resolution, leaving the home screen without any location or items.

**Fix:**
1. In `lib/features/location/helpers/location_utility.dart`:
   - Wrapped `getLeafLocationFromLatLng` in `_getLiveLocation()` with a `try/catch` block.
   - When the backend throws an error or no city is found, it automatically falls back to `_getPersistedLocation()` (`AppSession.currentLocation ?? AppConfig.defaultLocation`).
   - Ensured `getLocation()` always returns a non-null fallback (`location ?? AppSession.currentLocation ?? AppConfig.defaultLocation`).
2. In `lib/features/home/screens/mixins/root_location_resolver_mixin.dart`:
   - Wrapped `_getLocation()` in a `try/catch` block and ensured `_setLocation(AppConfig.defaultLocation)` is invoked if location resolution fails.
3. In `lib/features/location/screens/widgets/location_map/location_map_controller.dart`:
   - Wrapped `onTap` coordinate resolution in a `try/catch` to avoid crashes when users tap unlisted regions on the map.

**Admin Panel Configuration Recommendation:**
To have the backend resolve those specific coordinates to a city:
- Go to **Admin Panel → Locations → Cities** and add the desired city (e.g., Kolkata) with its center coordinates and radius, **OR**
- Go to **Admin Panel → Settings → Map Provider** and configure Google Maps Places/Geocoding API with a valid billing-enabled API key so the backend can geocode any location worldwide.
